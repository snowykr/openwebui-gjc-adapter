# Changelog

## [Unreleased]

### Added

- Added an OpenAI-compatible `/v1/models` and `/v1/chat/completions` gateway backed by the released GJC public SDK, with canonical `gjc/<provider>/<model>:<thinking>` model selection.
- Added live OpenWebUI projection for GJC reasoning, assistant text deltas, tool/MCP activity, subagents, todos, goals, notices, retries, compaction, artifacts, workflow progress, and terminal status.
- Added workflow-gate rendering and continuation, including persisted schema and lineage validation before a reply is resumed.
- Added project linking, listing, and unlinking from chat commands, project-folder/session-history projection, file attachment handoff, and safe folder-deletion reconciliation.
- Added managed and existing-install CLI configuration paths with readiness probing, resumable recovery journals, runtime-location configuration, and loopback/private-network defaults.
- Added a focused Chromium/OpenWebUI smoke test and CI policy, compatibility, lifecycle, and runtime validation coverage.

### Changed

- Production serving now consumes the public managed SDK from `@gajae-code/coding-agent` 0.16.4 with matching AI/native packages from the npm registry, replacing the hosted development tarball. The container uses pinned Bun 1.4.0 and the registry CLI. Both mode values require canonical V3 plus an active marker before startup effects; `SessionRouter.generationStatus` supplies positive exact-generation retirement evidence. Historical development contract evidence remains separate. Removed the raw bridge transport, descriptor-backed lifecycle contracts, CLI/tmux lifecycle source and container dependency; the public exact-close gap still blocks aggregate cutover approval.
- Recorded the SDK 0.16.4 exact-close contract gap: public binding APIs omit the opaque incarnation required to fence a remote close. Production close remains fail-closed; isolated session-ID-only harness closes and subsequent positive retirement do not prove replacement-race safety.
- Documented strict `GJC_OPENWEBUI_MODE` handling: only `managed` and `existing` are accepted; omitted, empty, whitespace-padded, case-variant, and other values fail closed with `GJC_OPENWEBUI_MODE must be exactly managed or existing`.
- Streamed assistant reasoning/text and lifecycle events while a turn is running instead of waiting for transcript completion. Workflow-gate continuations use the same streaming path.
- Kept GJC session JSONL and artifacts as historical projection sources while requiring managed authority and correlated public SDK terminal evidence for live operations; OpenWebUI rows remain projections and user-owned fields survive reprojection.
- Separated project identity from model identity and made the bare `gjc` model an input-only alias; emitted model ids are canonical normalized tuples.
- Made runtime path resolution deterministic and isolated from ambient `GJC_CONFIG_DIR`, `PI_CONFIG_DIR`, and `GJC_CODING_AGENT_DIR`.
- Clarified managed Docker feasibility prerequisites and existing-route ownership, separated adapter/OpenWebUI readiness from GJC provider/model availability, and documented picker-to-`DEFAULT`, profile, and role-assignment semantics without adding runtime controls.
- Updated the managed deployment default from OpenWebUI v0.10.0 to v0.11.0 while retaining the v0.10.0 minimum for existing deployments and the explicit `GJC_OPENWEBUI_IMAGE` override.
- Documented that OpenWebUI v0.11's stock regenerate/fork UI cannot carry adapter branch-control metadata to an OpenAI-compatible provider; direct branch controls remain fail-closed rather than inferred.

- Hardened the WAL durability semantics: failures after a mutation is durably committed (WAL append or base rename) surface as `SessionAuthorityDurabilityError` with the WAL-visible state retained instead of rolling back memory, so a retry cannot conflict with or duplicate a committed operation; unverified WAL rollbacks reload the replayable state; the WAL truncation is fsynced before a rollback is reported; deleting a failed new WAL syncs its directory entry; the WAL base binding now includes a per-rewrite document generation so timestamp-preserving external replacements cannot replay stale deltas (the live per-mutation verification re-checks that generation with a layout-independent streaming scan that also tolerates external whitespace formatting, and the cached WAL state is bound to a content digest so a same-size timestamp-preserving WAL replacement is replayed before the next append); failed post-commit reloads keep the durability-error classification (including post-fsync identity refreshes and the final post-rewrite base stat); a live reload that finds a crash-truncated WAL compacts the valid prefix before the next append (and a malformed non-final or newline-terminated WAL line fails closed instead of silently dropping the acknowledged mutations after it); each WAL delta carries its chained head (a hash committing to the entire prefix, computed over the line body), and the per-append check re-verifies the FULL on-disk chain (every link, bounded by the compaction threshold), so a same-stat interior or tail delta replacement or corruption fails closed before any acknowledged append; an unterminated final WAL line is treated as a torn tail even when it parses as valid JSON; a malformed WAL header fails closed instead of deleting the acknowledged deltas that follow (only a syntactically valid header demonstrably bound to another base is treated as stale; a malformed newline-terminated current-WAL delta fails closed instead of being ignored; and compaction synthesizes a compact gate binding from a legacy gate result's events before stripping them, so a superseded replay keeps its durable evidence); and the WAL is retained when a base rename's directory sync is uncertain, so a crash cannot leave the old base without its WAL-only mutations; the cached generation span check stays O(1) and sized from the serialized value; replayed legacy v1 WALs are compacted before the first append; and an unverifiable base (generation present with no serialized offset) is upgraded regardless of whether a WAL already exists; the live base-generation check reads a cached byte offset instead of scanning the document (offsets and digests are byte-consistent for non-ASCII content); WAL replay and rollback seed from internal references instead of deep-copying the whole authority; compaction rewrites the in-memory journal to the normalized records so stripped event arrays are not re-introduced by later WAL deltas; the migration preflight validates the generation value shape so malformed documents degrade instead of failing at startup; relocating a v2 authority compacts its validated WAL into the base first under the held source authority lock so WAL-committed mutations are never lost during migration, and the committed-candidate shortcut is not taken while a CURRENT source WAL exists (the check, made under the source authority lock, inspects the WAL binding: a stale WAL bound to a previous base or a header-only WAL (no replayable delta) is ignored, and a malformed or unreadable WAL fails closed, so neither a crash leftover nor an interrupted first append can force a pointless source rewrite and degrade an intact migration); and generation-less bases are rewritten with a fresh generation before the first WAL append instead of binding the WAL by stat only.
- Removed the per-mutation full-authority deep copy: mutation rollback snapshots are shallow copy-on-write references (the journal stores new objects on every change), so a mutation no longer allocates O(total-document-size) before appending a small WAL delta.
- Bounded boot memory for oversized legacy authority documents: boot now runs a one-time normalizing compaction (compact JSON, journal results without events) when the base document exceeds 64 MiB so a legacy 1 GiB-class file is shrunk in a single bounded step and later boots pay only the lean size, and boot projection synthesis iterates a copy-free `mappingRecords()` view instead of deep-copying every mapping and event payload.
